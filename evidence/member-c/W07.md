# C W7 — finite recovery and UNKNOWN

C-W07-01..07/10: FailurePolicy classifies validation, authorization, domain conflict, transient, unknown effect, poison, resource pressure and configuration. Retry metadata is validated and finite; error envelopes carry safe identity metadata. Unsupported schema is terminal poison, never a normal retry.

Payment alone owns provider retries. Normal replay does not retry. Explicit retry requires PENDING, enforces backoff from persisted UpdatedAt and a maximum of three attempts. UNKNOWN must reconcile first; no-effect can return to PENDING, existing effect resolves SUCCEEDED, exhaustion requires visible review. Separate provider commit occurs before a response-loss exception; Payment records UNKNOWN without assuming the effect happened. Same-key reconciliation queries independent provider authority. Replays after restart return canonical state.

.NET resilience is deliberately limited to bounded CancellationToken timeouts, bounded pools and explicit classified retry. No generic HTTP/provider automatic retry pipeline is stacked on top. There is no remote HTTP provider in this simulator. W8 uses the shared policy for broker delivery; W9 owns atomic dedup/Outbox. Long-term scheduled recovery belongs to later workflow integration; W7 exposes explicit development retry/reconcile controls and application methods.

Proof: PaymentRecoveryTests (real PostgreSQL), FailurePolicyTests, payment-smoke.py (real HTTP, DB and service restart). A/B Matching/Saga retry-owner review remains pending; do not treat implementation as independent review.
