# C W8 — broker backbone evidence

C-W08-01..10/12 map to ConfirmedPublisher, ManualAckConsumer, RideTopology and RabbitBackboneTests. Tests use real RabbitMQ 4.3.6 and PostgreSQL 18.6; no fake broker fallback. CI uploads TRX. Platform smoke also verifies 9 business + 9 error quorum queues, 3 durable topic exchanges, exact bindings and idempotent redeclaration.

Run: `dotnet test tests/Integration/RideHailing.Platform.IntegrationTests -c Release --filter FullyQualifiedName~RabbitBackboneTests --logger trx`

Proofs: broker confirm can arrive with no consumer; commit exists in PostgreSQL when consumer connection closes before ACK; the same delivery is then redelivered. This demonstrates the crash window, not W9's dedup solution. Mandatory unroutable publication throws. Valid handler receives correlated trace and ACK follows commit. Unsupported schema never calls handler; exhausted transient has four deliveries (initial + three retries) then confirmed error transfer. Broker stop causes visible publish failure and subsequent explicit call reconnects.

The live A/B workflow integration and C-W08-11 peer crash-window review remain team responsibilities. No main merge is performed. W9 Outbox/dedup and later broker HA are not claimed here. See src/BuildingBlocks/RideHailing.Messaging/README.md for host lifecycle and retry ownership.
